# codeTAC

**See what your app's code does, one action at a time.**

A local tool for Node.js and Python (FastAPI, Flask) web apps, including those generated by AI tools (Lovable, Bolt, v0, Cursor, Replit, Claude Code…).

![Dossier of a click on the “Sign in” button: the server functions that ran, with their file and line, and the database reads](https://raw.githubusercontent.com/deltaxmodules/codetacvibe/main/.github/imagens/dossier.png)

## Why

Your app was built by an AI, or by someone else, and you are not sure what happens when you press “Save”? Which functions run, which table changes, whether an email goes out, whether the payment is in test or live mode?

Click a button in your app and codeTAC shows a **dossier** of that action:
- **in the browser:** what was clicked, the component and where it is in the code;
- **on the server:** your project's functions that ran, in order, with the file and line;
- **the boundaries:** database, external services, email, payments, files, AI;
- **what changed on screen;**
- **the lasting effects:** rows written, emails sent, cookies…;
- a plain sentence on each step saying what it is for.

On any step, you can open that function's code and ask a question about it.

Everything runs on your computer. Your app's code is not changed.

## Which apps it works with

**Web apps in Node.js (JavaScript or TypeScript) or Python (FastAPI or Flask), running on your computer.** Including those made with Lovable, Bolt, v0, Cursor, Replit or Claude Code.

**Node.js — tested with:**
- Next.js (including version 16);
- Vite + React;
- Express;
- TanStack Start;
- projects with a separate frontend and backend, and monorepos (npm, pnpm, yarn).

Other Node apps should work (Nuxt, SvelteKit, Astro, Remix, NestJS, Fastify…), but have not been tested yet. If something fails, see [section 6](#6-when-something-does-not-work).

**Python — tested with:**
- FastAPI (`async def` and `def` functions), with uvicorn, `fastapi dev` or gunicorn;
- Flask, with `flask run`, `app.run()`, gunicorn or waitress, including Jinja templates;
- a Node frontend (for example Vite + React) with a Python API in the same folder or in a subfolder (`backend/`, `api/`…): they start together, and the dossier follows the browser click all the way to the Python functions;
- projects generated by Claude Code, Replit Agent, Lovable, Codex and Cursor.

To follow the app's functions, you need **Python 3.12 or newer**. With Python 3.8 to 3.11, codeTAC works in **minimal mode**: it shows the requests, the boundaries and the browser, but not the functions. With hypercorn or granian, the app runs, but actions get no dossier (the command warns you and suggests uvicorn).

**Shown separately when the app uses:**

| | |
| --- | --- |
| Database | Postgres (`pg`), MySQL (`mysql2`), SQLite (`better-sqlite3`, `node:sqlite`), Supabase (with the table and the operation). In Python: `sqlite3`, `psycopg2`, `psycopg`, `asyncpg`, `pymysql` and SQLAlchemy |
| AI | OpenAI, Anthropic, Google, Mistral, Groq, OpenRouter, DeepSeek, Cohere, Together, local models |
| Email and messages | nodemailer, Resend, SendGrid, Postmark, Mailgun, Brevo, Twilio |
| Payments | Stripe, showing test or live mode |
| Authentication | NextAuth, Supabase Auth, Clerk |
| Files | the computer's disk, S3, Supabase Storage |
| Other | any request from the server to an external service, cookies |

Services called directly from the browser (for example Supabase, in many Lovable and Bolt apps) show up as browser requests, without the server's step-by-step.

**Not supported yet:**
- Django, or apps in PHP, Go or Ruby (Laravel, Rails…);
- sites with only HTML and JavaScript, without a Node or Python server;
- parts that run on Bun, Deno, Cloudflare Workers or in Next.js middleware;
- apps in production or that only exist in the cloud.

You need Node.js 24 or newer, for Python apps too (codeTAC is installed with npm). Tested on macOS; Windows has not been tested yet.

## 1. Before you start

You need three things (four for Python apps):

1. **Node.js 24 or newer.** To check, open the Terminal and type `node -v`. It must show `v24` or a higher number. If it does not, install the LTS version from [nodejs.org](https://nodejs.org).
2. **Your app's project on your computer.** If the app was made with Lovable, Bolt, v0 or Replit, connect it to GitHub and download it:
   - on GitHub, **Code → Download ZIP**, and unzip the file;
   - or `git clone <address>`, if you use Git.
3. **A browser:** Chrome, Edge, Firefox or Safari.
4. **For Python apps only: Python 3.12 or newer.** To check, type `python3 --version`. If you do not have it, install it from [python.org](https://www.python.org/downloads/) (on macOS, also `brew install python`). If you have [uv](https://docs.astral.sh/uv/), codeTAC uses it, and it downloads any Python that is missing.

**How to open the Terminal:**
- **macOS:** Cmd+Space, type “Terminal”, Enter;
- **Windows:** Start menu, type “PowerShell”, Enter. codeTAC has not been tested on Windows yet.

## 2. Install

In the Terminal:

```sh
npm install -g codetac
```

Check with `codetac --version`, which shows the version number.

If you get a permissions error (`EACCES`), use `npx codetac` instead of `codetac` in the steps below. It works without installing.

## 3. Your first dossier

1. In the Terminal, go to the project folder: type `cd ` (with a space), drag the project folder into the Terminal window and press Enter.
2. Type:

   ```sh
   codetac
   ```

3. codeTAC says what it is going to start, for example `Start: Vite · npm run dev`.
   - If the app's dependencies are missing, it asks whether to install them. Press **Enter**, which means yes.
   - In a Python app without an environment, it asks whether to create the `.venv` in the project folder and install the dependencies (`requirements.txt`, `pyproject.toml` or `uv.lock`). **Enter** means yes.
   - If the project has a `.env.example` and no `.env`, it warns you: many apps need that configuration (copy the file to `.env` and fill it in).
   - If the project has several parts, it asks which ones to start. **Enter** starts them all.
4. When **“✓ App ready at http://localhost:…”** appears, the browser opens with your app.
   - For a FastAPI API, it opens the interactive documentation (`/docs`): each “Try it out” gets a dossier.
   - For a Node API without pages, the browser does not open: make requests as usual, and each one gets a dossier in the panel (the link shows up in the Terminal).
5. **Use the app:** click a button, a link, submit a form.
   - A small bar with “Recorded: …” shows up in the bottom right corner of the page.
   - The Terminal shows “✓ First dossier …” with a link.
6. Click the bar, or open the link, to see the dossier.
7. To stop, go back to the Terminal and press **Ctrl+C**.

For an app it already knows, the first dossier usually arrives in less than a minute.

## 4. Reading the dossier

- **The top sentence** sums up the action, for example: “Click on button “Add” → POST /api/items (status 201) → changes the screen”.
- **browser → server:** each request the action made to the server. Below it are your project's functions that ran.
- **Coloured tags** (“database”, “HTTP”, “email”…): the points where the app talks to the outside world.
- **▸** opens a group, for example repetitions or database setup. **Show all** shows the full sequence.
- **Click a function** to see its code and ask a question about that step.
- **request detail:** from the next action on, that function also records the values it received and returned, and the lines that ran.
- **Lasting effects:** what remained after the action (rows written, emails, cookies). “No lasting effect observed” means the action only read.
- **Minimal mode** (yellow strip): codeTAC could not follow the project's functions and shows only the requests, the boundaries and the browser. The strip says why.

## 5. AI explanations (optional)

With no configuration:
- if [Ollama](https://ollama.com) is running on this computer, codeTAC uses it, and nothing leaves the machine;
- if it is not, the sentences are built only from what was recorded.

To use Anthropic or OpenAI, create the file `~/.codetac/ai.json`:

```json
{ "provider": "anthropic", "key": "your-key" }
```

For OpenAI: `{ "provider": "openai", "model": "gpt-5.4-mini", "key": "…" }`.

Other options in the same file:
- **an OpenAI-compatible API:** `{ "provider": "compatible", "url": "https://…", "model": "…", "key": "…" }`;
- **turn AI off** (Ollama too): `{ "provider": "none" }`.

Instead of the file, you can use the variables `CODETAC_AI_PROVIDER`, `CODETAC_AI_MODEL`, `CODETAC_AI_KEY` and `CODETAC_AI_URL`, which take priority over it. `CODETAC_AI_CONFIG` points to another file.

With a cloud model, excerpts of the functions' code are sent, after secrets are removed. Recorded values are never sent. The panel shows what is being used.

- **“AI”** next to a sentence: the sentence came from the model and matches what was recorded.
- **“AI rejected”:** the model's sentence said something that was not observed. It was replaced by the sentence built from the facts. Hover over it to see why.

## 6. When something does not work

With the app running, in another Terminal window and in the same folder:

```sh
codetac diagnose
```

Each line starts with **✓** (works), **!** (warning) or **✗** (problem), with what to do.

| Message | What to do |
| --- | --- |
| “I did not find a package.json…” | You are in the wrong folder. Go to the folder that has the `package.json` file (or, for a Python app, the `requirements.txt`, the `pyproject.toml` or the `main.py`/`app.py`), or give the start command: `codetac -- node server.js`, `codetac -- uvicorn main:app` |
| “I found a Python project, but not the app…” | codeTAC did not find `FastAPI(...)` or `Flask(...)`. Give the start command: `codetac -- uvicorn main:app` or `codetac -- flask --app app run` |
| “This project uses Django…” | Django is not supported yet (FastAPI and Flask only) |
| “Port 3000 is already taken by another program…” | Close the other program, for example another app open in another Terminal window. For an app with a single part, codeTAC moves to another port by itself |
| “The app itself failed while starting: …” | The error comes from the app's own code, at the file and line shown, and would happen without codeTAC too. Often it is configuration: a folder, key or service in `.env` that does not exist on this computer (for example a production path such as `/var/lib/…`) |
| “The app failed in minimal mode too” | The problem is in the app itself. Often the keys in the `.env` file are missing (Supabase, Firebase…). Check the `.env.example` or the project's instructions |
| “The home page answered with error 500” | The app started, but fails. The dossier of that page load shows where |
| “…taken by the macOS AirPlay Receiver” | Flask's port 5000 belongs to AirPlay on macOS. codeTAC starts the app on another port; to use 5000, turn off “AirPlay Receiver” in System Settings › General › AirDrop & Handoff |
| “The project's Python is …” | The app runs on a Python older than 3.12. Create the `.venv` with a newer Python (delete the `.venv` and run `codetac` again) |
| “hypercorn is not recognised yet” (or granian) | Start the app with uvicorn, for example `codetac -- uvicorn main:app` |
| The bar does not show up on the page | Reload the page. Check that the address is the one codeTAC showed |

**Reporting a problem:**

```sh
codetac report
```

It saves the diagnosis to a file, with no code or data from the app. Send it with a description of what you did and what you expected at [github.com/deltaxmodules/codetacvibe/issues](https://github.com/deltaxmodules/codetacvibe/issues).

## 7. Privacy

- Everything stays on your computer, in `~/.codetac` (another folder with `CODETAC_HOME`).
- Before recording, secrets are removed: passwords, tokens, keys, emails and phone numbers.
- By default no values are recorded, only names, files and lines. Values are recorded only in the functions where you request detail.
- The panel only answers on this computer (`127.0.0.1`).

## 8. Commands

| Command | What it does |
| --- | --- |
| `codetac [folder]` | Starts the app with codeTAC |
| `codetac diagnose [folder]` | Explains what works and what does not |
| `codetac report [folder]` | Saves the diagnosis to attach to an issue |
| `codetac help` | All the options |
| `codetac --version` | The installed version |

**Options:**

| Option | What for |
| --- | --- |
| `--script <name>` | use another script from the `package.json` |
| `--part <folder>` | in a project with several parts, which one to start (can repeat) |
| `--port <n>` | the app's port, if it is not found automatically |
| `--panel-port <n>` | the panel's port (default 4000) |
| `--minimal` | do not follow the project's functions |
| `--yes` | answer “yes” to the questions |
| `--no-open` | do not open the browser |
| `-- <command>` | the start command, for example `codetac -- node server.js` or `codetac -- uvicorn main:app --reload` |

## 9. Limits

- The kinds of app that work and those that do not are in [Which apps it works with](#which-apps-it-works-with).
- It is meant for development, on your computer. It does not work for apps in production.
- Parts that run neither on Node nor on Python are not observed inside. The command warns you when it recognises them.
- In the browser, the element, the component and the path to each request are shown, but not each function.

**In Python apps:**
- Functions are followed only with Python 3.12 or newer. Below that, minimal mode: requests, boundaries and browser.
- The app is found when `FastAPI(...)` or `Flask(...)` (or a `create_app` factory) is in a `.py` file up to two folder levels below the given folder. Otherwise, give the start command with `codetac -- <command>`.
- The app's configuration (`.env`, database, Redis…) is yours: without it, codeTAC shows the app's own error.
- Threads created by hand (`threading.Thread`) are not linked to the request that created them; FastAPI's and `asyncio`'s are.
- Redis, MongoDB and Celery do not show up as boundaries yet: the time spent in them stays inside the function that called them.
- Pages sent in chunks (streaming) do not get the bar; the action is still recorded.
- With many queries per page, the server gets slower: on a page with 52 SQL queries, it went from 1.0 to 2.8 ms. In the other apps tested, the time stayed between 1 and 1.3 times the normal.
- MySQL through `mysqlclient` and Django have not been tested yet.

## Upgrading from 0.2

Version 0.3.0 is in English and renames the commands and options:

| 0.2 | 0.3 |
| --- | --- |
| `codetac diagnostico` · `relatorio` · `ajuda` | `codetac diagnose` · `report` · `help` |
| `--parte` · `--porta` · `--painel` | `--part` · `--port` · `--panel-port` |
| `--minimo` · `--sim` · `--nao-abrir` | `--minimal` · `--yes` · `--no-open` |
| `~/.codetac/ia.json` | `~/.codetac/ai.json` |
| `"provider": "nenhum"` · `"compativel"` | `"provider": "none"` · `"compatible"` |

`CODETAC_LANG` no longer exists: explanations are always in English. Recordings made with 0.2 still open.
